# Acme Button Library (ForgeGate fixture)

A small, real, deterministic Web Components package — not a demo product. It exists so ForgeGate's own development and automated tests have a real workspace to point at, per [`documentation/decisions/0003-pilot-repository.md`](../../documentation/decisions/0003-pilot-repository.md):

> Build a small, purpose-built, deterministic fixture repository later, specifically for ForgeGate's own CI. The fixture exists to keep ForgeGate's automated tests reliable and independent of an external repository's drift.

Contents:

- [`src/acme-button.js`](src/acme-button.js) and [`src/acme-card.js`](src/acme-card.js) — real, working vanilla `HTMLElement` custom elements (no build step, no framework), documented with real JSDoc so static analysis can pick up their public surfaces.
- [`custom-elements.json`](custom-elements.json) — generated by the real tool ForgeGate's own "Generate Custom Elements Manifest" feature shells out to, not hand-written. Regenerate it after editing `src/acme-button.js`:
  ```bash
  cd fixtures/acme-button-library
  npx @custom-elements-manifest/analyzer analyze --litelement --outdir .
  ```
- [`tokens/acme.tokens.json`](tokens/acme.tokens.json) — a real DTCG-format token file.
- [`.forgegate/components/acme.button-library.acme-button.yaml`](.forgegate/components/acme.button-library.acme-button.yaml) and [`.forgegate/components/acme.button-library.acme-card.yaml`](.forgegate/components/acme.button-library.acme-card.yaml) — repository-controlled ForgeGate manifests that map required states, stories, and DTCG token paths without replacing CEM-derived public contracts.
- [`test/acme-button.test.js`](test/acme-button.test.js), [`test/acme-card.test.js`](test/acme-card.test.js), [`.forgegate/evidence/acme-button-unit.json`](.forgegate/evidence/acme-button-unit.json), and [`.forgegate/evidence/acme-card-unit.json`](.forgegate/evidence/acme-card-unit.json) — real dependency-free `node:test` executions and normalized ForgeGate results. Raw TAP artifacts remain under `.forgegate/evidence/raw/` when present.
- [`src/content/docs/components/button.md`](src/content/docs/components/button.md) — a repository-owned Button documentation target used by drift-detection fixtures.
- [`src/content/docs/components/acme-button--for-designers.mdx`](src/content/docs/components/acme-button--for-designers.mdx) and [`src/data/forgegate/components/acme-button--for-designers.json`](src/data/forgegate/components/acme-button--for-designers.json) — a checked-in ForgeGate generated Starlight designer page plus its companion report-data artifact. The MDX imports the real local `@forgegate/starlight` presentation package, imports `forgegateReport` from the companion JSON file, and passes that manifest-backed report with automated evidence, manual review, finding summaries, attachment references, and redaction posture into the presentation components. The page is screenshot-checked at desktop and mobile widths during local polish work.
- [`src/content/docs/components/acme-button--for-developers.mdx`](src/content/docs/components/acme-button--for-developers.mdx) and [`src/data/forgegate/components/acme-button--for-developers.json`](src/data/forgegate/components/acme-button--for-developers.json) — a second checked-in generated report route for the same real Button component. It keeps the fixture honest while proving that discovery and registration handle more than one report-data file and route.
- [`src/content/docs/components/acme-card--for-designers.mdx`](src/content/docs/components/acme-card--for-designers.mdx) and [`src/data/forgegate/components/acme-card--for-designers.json`](src/data/forgegate/components/acme-card--for-designers.json) — a checked-in generated designer report for a second real component, proving Starlight discovery and route injection are multi-component, not just multi-template.
- `astro.config.mjs` installs `forgeGateStarlightIntegration({ filesystemDiscovery: true, routeInjection: true, routeBase: 'forgegate/reports' })`, so `pnpm nx run starlight:fixture-build` exercises plugin discovery, route registration, and generated Astro route injection against these real report-data files while building the Starlight site. The build emits the checked-in generated MDX routes under `/components/` and plugin-injected routes under `/forgegate/reports/`.
- [`src/content/docs/components/index.mdx`](src/content/docs/components/index.mdx) and [`src/data/forgegate/components/index.json`](src/data/forgegate/components/index.json) — the generated registry-index companion page/data pair, covering the same JSON-import path as component reports. The registry page imports Button and Card reports too, so embedded status and evidence blocks render real designer-facing data rather than empty placeholders.

`apps/forgegate-desktop/src/generate-cem-command.spec.ts` runs that exact command (via `GENERATE_CEM_COMMAND`/`GENERATE_CEM_ARGS`, no mocks) against a disposable copy of this fixture — the regression test for the real `npm error 404` a user hit when those constants had a misspelled package name (`.../analyze` instead of the real `.../analyzer`) and were missing the required `analyze` subcommand.

This package is intentionally outside the pnpm/Nx workspace (no `pnpm-workspace.yaml` entry, excluded from ESLint via `fixtures/**` in `eslint.config.mjs`) — it is content ForgeGate scans, not code ForgeGate builds. `apps/forgegate-desktop/src-tauri/src/workspace_scan.rs`'s `detects_the_acme_button_library_fixture_correctly` test scans this directory for real and asserts on the result, so any future edit here that breaks detection fails CI immediately.

Run the configured fixture evidence with:

```bash
npm test
```
